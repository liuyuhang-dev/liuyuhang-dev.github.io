AI 研发项目 · 0→12026

让每个节点都有证据

十人并行、上百个页面，没人说得清进度；AI 生成快，但产出没人敢签收。

  • 四层拆解：版本 → 功能 → 工序链 → 承担人
  • AI 只提议，人确认才落库——治理边界写进流程
  • 每个节点挂 Git 提交作为证据，逾期可视化

从「没人说得清进度」到「每个节点都有证据」。

质量体系 · 评测基线2026

让报告不说谎

让 AI 既玩游戏又判对错，等于自己出题自己判卷——它不会报错，它会把 bug 固化成预期。

  • 玩判分离：执行与判定不能是同一主体
  • 期望不来自观察：只来自需求 / 不变量 / 配置 / 源间一致
  • 没证据不判通过：能力缺失记 blocked

宁可要「30 通过 / 20 blocked / 5 人工」的诚实报告。

工具化 · 自动化2025–2026

把协议藏进目录结构

美术走 SVN 交付，靠口头通知 + 人工提交：漏交没人发现、同名互相覆盖、半截文件被提交。

  • 美术只需把文件拖进一个文件夹，其余全自动
  • 文件名即数据结构：单号_资源名_用途.png
  • 传完判定：大小与时间连续多轮不变才收

核心不是 SVN，是把协议藏进目录结构里。

质量体系 · 完备性2026

让漏测无处可藏

靠「想」一定漏。人的注意力顺着正常流程走，而边界、重复、中断、竞态跟正常流程正交。

  • 每条需求子句 × 每个维度 = 一个格子
  • 格子只有三态：适用给产出 / 不适用给理由 / 未判断不允许
  • 第二张表：21 条需求没写、但必须成立的常识

完备性是乘出来的，不是想出来的。

02

方法

三句可以拿去反驳我的话。

01

生成越便宜，判断越贵

AI 压缩的是「做出来」的成本，没有压缩「证明它是对的」的成本。站位应该选在判断和放行那一侧。

02

能被执行的思想才是资产

「我重视质量」没有价值。有价值的是能跑的检查脚本、一张门禁表、一套判定词表。

03

诚实的边界比全能可信

判不了的说判不了、没证据的说没证据。报告的代价是会显得「不够绿」，但那是真实状态。
